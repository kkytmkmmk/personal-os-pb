# 日常利用 UX Audit

対象はVerification DBだけで起動したローカルアプリであり、本人情報・本番DB・添付画像は使用しない。

## 実施条件

- Desktop: 1280 × 720
- Mobile: 390 × 844
- URL: `http://127.0.0.1:8877/`
- データ: 検証用のSynthetic記録のみ

## 修正前の観察

| Journey | 観察した問題 | 操作上の影響 |
| --- | --- | --- |
| 起動 → 今日 | 今日の上部に相談・記録の入口がなく、状態カードと管理的な表示が先行する | 次の操作が分かりにくい |
| 記録 | 自然文入力、構造化抽出、受信箱追加、画像取込が同一画面に並ぶ | 同じ「覚えておいて」の目的に3つ以上の入口があった |
| 相談 | 回答と根拠が同じ面積で表示され、根拠が初期表示される | まず回答を読む導線が弱い |
| 判断 | 結果・評価がBrowserの`prompt()`入力だった | モバイルで入力途中を守れず、文脈も不足する |
| 探索 | ベンチマークのJSON取込欄が通常閲覧画面に常時ある | 比較結果より管理操作が目立つ |
| Mobile | Bottom Navigationは存在する一方、その他内の探索が管理相当の場所にあり、Primary Navigationは中間幅で横scrollする | 日常導線と管理導線が混ざる |

## 是正後の受入観点

| Journey | 期待する操作数 | 受入条件 |
| --- | --- | --- |
| 起動 → 相談 | 1 tap/click | 今日の先頭に「相談する」がある |
| 起動 → 記録 | 1 tap/click | 今日の先頭とMobileの＋が同じ記録画面へ進む |
| 記録 | 1つの本文入力 | 通常時は分類、タイトル、タグを要求しない。画像は同じ記録導線から追加する |
| 相談 → 根拠 | 1 additional tap/click | 回答が先にあり、根拠は折りたたまれる |
| 判断 → 結果/評価 | 1 tap/click | Sheetで入力し、途中入力はsessionStorageに保持する |
| 探索 → Benchmark取込 | 1 tap/click | 閲覧画面を圧迫せず、追加操作はSheetに隔離する |
| Mobile Draft | 画面移動後に戻る | 記録・相談・画像補足・Benchmark取込・判断結果の入力が残る |

## 既知の制約

- 相談・記録・判断の既存ローカルAPI、SQLite Schema、Provider Adapterは変更しない。
- 技術詳細は管理/診断または明示的な詳細表示に残す。日常画面の主導線には出さない。
- 取込、解析、バックアップは管理メニューからのみ扱う。

## Verification結果（2026-07-29）

フェーズ2〜5の実装・回帰保護の対応表は [UXフェーズ2〜5トレーサビリティ](ux_phase_2_to_5_traceability.md) を参照する。Browserの画面読取はVerification環境で確認した。一方、この実行環境ではBrowser制御層がクリック実行時に `SyntaxError` を返すため、Browser操作自動化の再実行はPartialとして記録する。

- Desktop 1280 × 720: 今日の「相談する」「記録する」、領域Menu、探索内のBenchmark取込Sheetを確認した。
- Mobile 390 × 844: Bottom Navigationの全Touch Targetが44px以上で、横Overflowがないことを確認した。`＋ → 記録 → 相談 → その他 → 記憶` の遷移後も記録Draftが残った。
- 判断: 「結果を記録する」からSheetを開き、閉じて再度開いても結果・良かった点のDraftが残ることを確認した。
- Verification環境内のSynthetic判断のみを作成して確認した。本番DB、本人情報、添付ファイルは使用していない。
